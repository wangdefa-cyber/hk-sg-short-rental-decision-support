# 数据处理说明

## 1. 原始数据保护

所有 `data/raw/` 文件只读。清洗结果写入 `data/processed/`，不覆盖原始文件。

## 2. 房源数据处理

1. 解析 `price` 字符串为数值，去除货币符号和千分位。
2. 使用 `price_quote_raw` 提取报价币种、是否月租定价和是否可订。
3. 通过城市 × 房型 1% 和 99% 分位识别异常价格，生成 `price_outlier`，保留原价格。
4. 使用 `price_clean` 作为描述统计和房价模型的可选目标变量。
5. 从 `bathrooms_text` 解析卫浴数、是否共享、是否独立。
6. 将房型映射为中文类别。
7. 对经纬度使用城市合理边界校验。
8. 根据房东房源数量划分单房源、小型多房源和专业多房源房东。
9. 将 `estimated_occupancy_l365d` 解释为估计入住晚数，保留 0–365 晚，并计算 `occupancy_estimate_rate = 晚数 / 365`。
10. 将评分、评论数、可订天数和最低入住天数转换为数值，并保留缺失。

## 3. 日历数据处理

1. 统一日期格式。
2. 将 `available` 的 `t/f` 转为布尔值。
3. 删除同一房源同一天期的重复记录。
4. 生成年、月、年月、星期和周末字段。
5. 只按可订率分析，不把不可订直接解释为已入住。

## 4. 评论数据处理

1. 统一日期格式。
2. 清理 HTML 标签、HTML 转义和多余空白。
3. 按 `city_key + review_id` 去重。
4. 记录原始行数、非法日期数和重复评论数。
5. 保留原始评论和清洗后评论，便于核查。

## 5. 数据集成

- `dim_listing.listing_key = city_key + ":" + listing_id`
- `dim_listing.host_key = city_key + ":" + host_id`
- `fact_calendar.listing_key` 关联 `dim_listing.listing_key`
- `fact_review.listing_key` 关联 `dim_listing.listing_key`
- 香港和新加坡对同日历和评论关联均无未匹配键

## 6. Google Trends 处理

1. 识别每个 CSV 的 `Time` 日期列和单一关键词列。
2. 统一为 `year_month` 月度长表。
3. 对每条序列分别计算 z-score，避免把独立归一化的 0–100 指数直接跨文件比较。
4. 计算首尾三个月均值、线性斜率、月度变化和完整年份的季节性。
5. 与月度评论活动分别进行水平值相关和月度变化相关，并报告 0–3 个月滞后。
6. 所有 Google Trends 文件均保留原始 CSV 和 SHA256。

## 7. 存储

- 大型事实表：Parquet
- 维度表和汇总结果：SQLite
- 地图边界：GeoJSON
- 数据版本和输出清单：`data/processed/warehouse_manifest.json`

## 8. 已知问题

- 香港、新加坡价格缺失约 15%。
- 两城 `bathrooms` 原始字段为空，已改用 `bathrooms_text`。
- 香港 `license` 全空，不能据此判断合法性。
- 新加坡 `license` 有缺失，也有不同许可文本，需按类别解释。
- `estimated_occupancy_l365d` 的数值与 `estimated_revenue ≈ price × nights` 一致，按入住晚数而不是入住率解释。
- 评论 ID 在原始数据中存在重复，已按城市内评论 ID 去重。
- Google Trends 已导入 8 个真实文件，7 条月度序列共 427 条观测，无缺失值。
